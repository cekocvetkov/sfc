In this article, we will look at object detection using YOLOv12, OpenCV, and Java.

**YOLO (You Only Look Once)** is one of the most famous object detection systems. It achieves very high speed and accuracy and is one of the easiest ways to get into object detection. The documentation is absolutely perfect, everything is very well explained with lots of examples. It also has a big community of researchers, developers, and enthusiasts who contribute to the project.

I started playing around with YOLO through Python. The integration is so smooth, and I was really impressed by how fast one can start experimenting with object detection. Inference can be done literally in 4 lines:

```python
from ultralytics import YOLO
# Load the YOLOv12 model
model = YOLO("yolo12n.pt")
# Run predictions
results = model.predict('/paht/to/image')
# Display results
results[0].show()
```

Let’s set up some basics next, before moving to the object detection part. I usually start by just reading and showing an image with OpenCV to make sure we got the setup correctly. We’ll load the OpenCV library, then read an image from our resources folder and show it using OpenCV `HighGui`:

```java
import nu.pattern.OpenCV;
import org.opencv.core.Mat;
import org.opencv.highgui.HighGui;
import org.opencv.imgcodecs.Imgcodecs;

public class ObjectDetectionONLY {
    private static final String IMAGE_NAME = "vase.jpg";

    public static void main(String[] args)
    {
        OpenCV.loadLocally();

        String imagePath = ResourceUtils.getResourcePath(IMAGE_NAME);

        Mat image = Imgcodecs.imread(imagePath);

        HighGui.imshow( "Image", image );
        HighGui.waitKey(0);

        HighGui.destroyAllWindows();
        System.exit(0);
    }
}
```

I like to prepare some utility classes when working with the file system. It allows me to then focus on the object detection and not think about where to load the images or models from. Here is my _ResourceUtils.java_ helper:

```java
import java.net.URL;

public class ResourceUtils {
    public static String getResourcePath(String resourceName){
        URL resourceUrl = App.class.getClassLoader().getResource( resourceName );
        if(resourceUrl == null){
            throw new RuntimeException("Resource with name "+resourceName+ "not found");
        }
        String resourcePath = resourceUrl.getPath();
        if(resourcePath.isEmpty()) {
            throw new RuntimeException("Error on getting path from resource URL");
        }
        return resourcePath;
    }
}
```

Alright, now that we have OpenCV in place and we can read and show images, we get to the more interesting part.

We’ll use the OpenCV [Deep Neural Network module](https://docs.opencv.org/3.4/d6/d0f/group__dnn.html), which is a perfect starting point for any beginner to get into deep-learning-based computer vision and experiment a bit. Models trained in frameworks like PyTorch or TensorFlow must be converted to the ONNX (Open Neural Network Exchange) format in order to be used directly with the OpenCV DNN module. And that’s what we’re going to do next. Luckily, the conversion of a YOLO Model to `.onnx` is very simple. You can do it with the [YOLO CLI or with Python](https://docs.ultralytics.com/modes/export/). We’ll use the [YOLOv12](https://docs.ultralytics.com/models/yolo12/) model, which is the latest version available at the time of writing. I recommend using Python through [Google Colab](https://colab.research.google.com/) for this. Just create a new notebook and add the following code cell:

```python
from ultralytics import YOLO
model = YOLO("yolo12n.pt")
success = model.export(format="onnx")
```

Run the code from above, and after this, just download the `yolo12n.onnx` model and save it to your `resources` folder in the Java project.

Our next steps will be:

1. Prepare the input image for the model
2. Load the model
3. Run the inference
4. Extract the bounding boxes from the results
5. Visualize the results

We start by preparing the image for the YOLOv12 model. This step includes the resizing ([IMG_SIZE is 640px for this YOLO model](https://docs.ultralytics.com/models/yolo12/#__tabbed_1_1))

```java
// this step includes swap BGR to RGB
Mat inputBlob = Dnn.blobFromImage(image, 1.0 / 255.0,
                new Size(IMG_SIZE, IMG_SIZE),
                // Here we supply the spatial size that the Convolutional Neural Network expects.
                new Scalar(new double[]{0.0, 0.0, 0.0}),
                true, false);
```

The last two boolean flags are:

- **swapRB**: flag which indicates that swapping first and last channels in a 3-channel image is necessary (in OpenCV, the default image format is BGR instead of the more common RGB, that’s why we set this flag to **_true_**)
- **crop:** flag which indicates whether the image will be cropped after resizing or not

The next step is to load our model and set our image blob as an input to the network:

```java
String modelPath = ResourceUtils.getResourcePath(MODEL_NAME);
Net net = Dnn.readNetFromONNX(modelPath);
net.setInput(inputBlob);
```

Now it’s time to feed the input data through the network and get the output predictions:

```java
Mat outputs = net.forward();
```

After we ran our input image through the network, we got a [Mat](https://docs.opencv.org/3.4/d3/d63/classcv_1_1Mat.html) output object — this is short for “Matrix” and is OpenCV’s primary data structure for storing images or numerical data. These are our **Bounding Box Predictions.**

Let’s print out the prediction results, which are saved in the `outputs` :

```java
LOGGER.info("Boxes Output: "+outputs.toString());
```

And let’s concentrate on its dimensions, here the log line:

```bash
INFO: Boxes Output: Mat [ 1*84*8400*CV_32FC1, isCont=true, isSubmat=true, nativeObj=0x600003378000, dataAddr=0x15ada8000 ]
```

We see that it has a shape of **[1, 84, 8400]**. Let’s break it down:

The `outputs` matrix contains predictions for **8400 potential detections**, where each detection has **84 values (4 for bounding box and 80 for class probabilities)**. The 1 is the batch size, meaning one image is processed.

So, for every one of the **8400 predictions**, we have a **vector of 84 values** that has the following structure:

- **4 values** for bounding box coordinates (center_x, center_y, width, height)
- **80 values** for class probabilities (80 is the number of classes the model was trained to detect — [COCO dataset](https://cocodataset.org/#home))

> **Note:** The previous statement only applies for YOLO versions ≥ 8.<br />
> YOLO5, for example, has a different output shape:<br />
> `(batchSize, 25200, 85) (Num classes + box[x,y,w,h] + confidence[c])`<br />
> It uses anchor boxes, with 3 anchors per grid cell, influencing the number of predictions (25200 = 8400 × 3). We’re not going to get into details here — just wanted to briefly mention it as a side note. If you have any questions, feel free to ask in the comments.

You probably noticed that the boxes output had the structure **1 x 84 x 8400**, but we talked about having 8400 predictions, **and for each one of them, 84 values**. In order to work with this logic properly, we need to transpose the matrix to **8400 x 84**. Luckily, this can be done easily with OpenCV in Java:

```java
Mat mat2D = outputs.reshape(1, (int) outputs.size().width); // The second parameter is the number of rows
Core.transpose(mat2D, mat2D);
```

This will change the structure of our `mat2D` object to **8400 x 84.**

Now we can extract the relevant information from the output. This is going to be our plan:

1. **Interate over every one of the 8400 rows**
2. **For every row, extract the 80 class probabilities and find the maximum.**
3. **Check this maximum (we can also call this “score”) against a defined threshold** (for example, only take predictions that have a score > 0.6)
4. **Extract the bounding box coordinates**
5. **Draw the bounding box coordinates**

```java
var box = new Rect2d();
var className = "";
for (int i = 0; i < mat2D.rows(); i++) {
    List<Double> scores = new ArrayList<>();
    for (int j = 4; j < COCO_CLASSES.length + 4; j++) {
        scores.add(mat2D.get(i, j)[0]);
    }

    MaxScore maxScore = ScoreUtils.findMaxScore(scores);
    if (maxScore.maxValue() < 0.6) {
        continue;
    }

    double width = mat2D.get(i, 2)[0];
    double height = mat2D.get(i, 3)[0];
    double x = mat2D.get(i, 0)[0] - (0.5 * width);
    double y = mat2D.get(i, 1)[0] - (0.5 * height);
    box = new Rect2d(x, y, width, height);
    className = COCO_CLASSES[maxScore.indexOfMax()];
    break;
}
```

This code snippet seems simple, but it requires an understanding of the underlying structure. Let’s walk through it to really lock it in:

The for-loop iterates through all 8400 prediction rows. For every row, with structure:

The values from **index 0** to **index 3** are the **bounding box predictions**.

For our object detection, we first go through the class probabilities (from index 4 to index NUM_CLASSES [80 in our case]) and find the maximum. We call this `maxScore` — the class with the maximum score is the class of the object that the model found.

The code for `ScoreUtils` is really just finding the max value from a double array, very simple. We also keep the class index in the `MaxScore` object:

```java
record MaxScore (double maxValue, int indexOfMax) {}

public class ScoreUtils {

    public static MaxScore findMaxScore(List<Double> array) {
        double max = array.get(0);
        int indexOfMax = 0;
        for (int i = 1; i < array.size(); i++) {
            if (array.get(i) > max) {
                max = array.get(i);
                indexOfMax = i;
            }
        }
        return new MaxScore( max, indexOfMax );
    }
}
```

After we find the `maxScore`, we check if it’s above a given threshold, we chose **0.6** here. If that’s not the case, we just move to the next prediction.

If the `maxScore` **is above 0.6,** though, we go ahead and extract our bounding box coordinates, save them in the `box` variable, get the class name of the bounding box prediction, and break the loop.

Now, this is a simplified approach in the spirit of this tutorial. The reason we’re breaking out of the loop here is that we know we only have ONE object to detect in our image. Even if there’s only one object, though, the model usually finds many similar, almost completely overlapping bounding boxes for the same object. **Non-Maximum Suppression (NMS)** is the standard technique to handle this. **NMS** keeps only the best detection and removes redundant overlapping boxes.

> This step is not too complicated and can be achieved fairly easily with OpenCVs `Dnn.NMSBoxes` function. Let me know in the comments if you need some help with this.

But, as I said, in order to simplify this, we skip this step — Without **NMS (non-maximum suppression)** for overlapping boxes, we get very similar bounding box predictions. If we just take one of them, we definitely got a hit (of course, this only works for one object per image).

Now we’re already at the easy part — We have a bounding box prediction — let’s just draw it over the image along with the name of the class it belongs to:

```java
Point xy = new Point(box.x, box.y);
Point wh = new Point(box.x + box.width, box.y + box.height);

// In order to draw the boxes correctly, we need to resize the image
Mat resizedImage = new Mat();
Imgproc.resize(image, resizedImage, new Size(IMG_SIZE, IMG_SIZE), Imgproc.INTER_AREA);

Imgproc.rectangle(resizedImage, wh, xy, new Scalar( 0, 165, 255 ), 2);

Point text_point = new Point(box.x, box.y - 5);
Imgproc.putText(resizedImage, className, text_point, Imgproc.FONT_HERSHEY_SIMPLEX, 1, new Scalar( 0, 165, 255 ), 2);

HighGui.imshow( "Image", resizedImage );
HighGui.waitKey(0);

HighGui.destroyAllWindows();
System.exit(0);
```
